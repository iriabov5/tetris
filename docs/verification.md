# Проверка реализации

Проверено 24 ноября 2026 года на JDK 21 и Node 26.13.1.

| Проверка | Результат |
|---|---|
| Backend | Чистая Maven-сборка clean verify прошла |
| Ядро | 103 проверки, ошибок и пропусков нет |
| API | 30 HTTP-проверок на реальном сервере, 3 проверки артефакта OpenAPI и 8 проверок событий Logback прошли |
| JaCoCo | 98,9% строк и 98,7% ветвей в агрегированном отчёте core и api; пороги 80% сохранены |
| JavaDoc | Production- и test-документация обоих модулей прошла DocLint all с видимостью private и failOnWarnings |
| Frontend | 56 компонентных проверок и 3 проверки транспорта в семи файлах прошли |
| Генератор клиента | 2 Node-теста: дрейф файлов и сохранение SDK при ошибке; LCOV собственного скрипта — 83,5% строк |
| Проверки фронтенда | TypeScript strict, ESLint, Prettier и production-сборка прошли |
| Playwright | 19 сценариев в шести файлах прошли, включая Swagger UI |
| Поле 10 × 20 | Отдельный браузерный проход проверил 360, 768 и 1440 px, паузу, загрузку, ошибку, восстановление и окончание партии |
| SonarQube | Quality Gate OK, открытых замечаний и security hotspots нет; покрытие 86,4%, дублирование 0% |

Выполнены `make api-generate`, `make check`, `make e2e` и локальный SonarQube-анализ итоговой версии с подсказками клавиш на кнопках. Полный набор содержит 144 Java-теста, 59 frontend-тестов, 2 Node-теста и 19 Playwright-сценариев. Повторная полная цепочка Java → OpenAPI → SDK дала побайтово одинаковые файлы клиента.

В Sonar импортированы JaCoCo, Vitest LCOV и Node LCOV собственного скрипта генератора. Генерируемые шаблоны исключены из анализа Sonar и метрики Vitest, но проверяются TypeScript, ESLint, Prettier и поведенческими тестами вызовов. Общее покрытие Sonar также включает прежние вспомогательные скрипты без отчёта покрытия; показатели Java указаны отдельно.

Java-тесты разделены по размещению и закреплению клеток, выпуску, перемещению и повороту фигур, жизненному циклу, снимкам и расширяемости. HTTP-проверки создания, чтения, команд, валидации, конкурентности и завершения выполняются в отдельных классах. Тесты используют Arrange, Act и Assert, русские @DisplayName и независимые фикстуры.

Проверки Swagger сравнивают JSON и YAML работающего API с экспортированным контрактом, обязательность и nullable полей, ограничения геометрии, enum, статусы, Location и ошибки problem+json. Проверено обнаружение удалённого HARD_DROP, отсутствие ложного расхождения при перестановке ключей/required и сохранение файла при невалидном экспорте. При выключении документации UI и схемы возвращают 404, игровые команды работают. Playwright создаёт партию и выполняет LEFT через Try it out на порту, отличном от 8080, без запросов к внешним ресурсам.

HARD_DROP проверен у дна, на препятствии, при нулевой дистанции и после поворота, при очистке строк и завершении, при отказе источника и повторе после восстановления. Пауза проверена при смене скорости, успешной и ошибочной новой игре, незавершённом запросе, восстановлении и завершении. Браузерный сценарий подтверждает независимость вкладок.

Клавиатура проверена на реальных запросах, нативном Пробеле кнопки, списке скорости, модификаторах, IME, повторах, загрузке, ошибке, окончании и размонтировании. Управляемые часы исключают ожидание реального падения. Тесты Logback проверяют уровни, UUID, результат, стек исключения, фильтрацию INFO и однократное окончание. HTTP-проверка сбоя подтверждает безопасный problem+json 500 и сохранение партии.

В README сохранены пять игровых скриншотов и добавлены ссылки Swagger, JSON/YAML и команда экспорта. Обновлены макеты и скриншоты: подсказки клавиш перенесены на кнопки, на узком экране бейджи скрыты. Ссылки и 15 фрагментов кода в game-flow.md сверены с реализацией.

Клиентские операции и модели генерируются Orval из docs/openapi.yaml. Ручные api.ts/types.ts удалены; React и фикстуры используют сгенерированные типы. Проверены изменённый, отсутствующий и лишний файл SDK, отсутствие перезаписи при проверке, очистка временных каталогов и сохранение прежнего SDK на невалидном YAML. Общий транспорт проверен на HTTP 500, сетевую ошибку и таймаут без повторов POST; восстановление состояния и остальные игровые сценарии прошли через SDK.

Для переноса подсказок на кнопки выполнены make check, make e2e и локальный SonarQube-анализ. Существующие проверки клавиатуры и доступных имён кнопок прошли. Браузерные проверки на ширинах 360, 768 и 1440 px подтверждают скрытие бейджей на узком экране и видимость на компьютере; отдельно проверено отсутствие переполнения кнопок. Обновлены четыре макета и шесть скриншотов README. Quality Gate OK, открытых замечаний и security hotspots нет.
